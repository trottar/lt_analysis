# Known gaps and intentionally unresolved history

## 1. Not a literal transcript export

This package reconstructs substantive KaonLT development/scientific history. It does not guarantee every sentence from every historic ChatGPT conversation is present.

Literal chat exports should be archived/indexed separately if desired; they should not be dumped into active memory.

## 2. Exact final Phase-D farm provenance is incomplete here

Later project state treats Phase D as frozen comparison/closure infrastructure, but this import does not contain one final Phase-D bundle/manifest with evaluated commit, settings, checker results, rendered pages, and closure statement.

Do not fabricate those details.

## 3. Final five-setting E.3 closure is not established by the recovered Left-low handoff alone

Direct recovered evidence proves:

```text

```

That handoff explicitly says the next task was the remaining four settings/final five-setting validation.

Later Phase-F work implies the project moved on, but runtime closure for those four settings must not be inferred solely from sequence.

## 4. Some older proton farm details are distributed across chats/contracts

The history clearly contains farm-driven proton repairs and a protected-Lambda gate, but this import does not reconstruct every per-setting timing-fit numeric result.

Prefer exact CSV/JSON/PDF evidence if available.

## 5. Generic June commit subjects are chronology only

Subjects such as:

```text

Background implementation | 4
```

must not be used to assign scientific phase status without source/diff review.

Recompute `CURRENT.md`/handoff after deep migration rather than preserving the old next step automatically.
